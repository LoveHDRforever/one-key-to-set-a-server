# 玩家各类数据的存放位置（运维速查）

> 适用版本：**onekeytosetaserver 0.2.5**（Minecraft 1.20.1 / Forge 47.x）
> 一句话结论：**原版的玩家数据（背包 / 位置 / 成就 / 统计）全在主城文件夹 `mainland/` 下；
> 本 mod 加的玩家数据全在 `multiverse/` 与"各世界文件夹的 `multiverse/`"里；货币在主城存档的 `data/` 下。**

---

## 0. 一张总表

| # | 玩家数据 | 具体文件 | 由谁写 | 什么时候写 | 丢了会怎样 |
|---|---|---|---|---|---|
| 1 | 位置、血量、饥饿、经验、效果、末影箱、**主背包 + 盔甲 + 副手**（未开独立背包时） | `mainland/playerdata/<uuid>.dat` | 原版 | 自动存档 / 退出 / 停服 | 回到上次存档的状态，严重时等于回档 |
| 2 | 成就 | `mainland/advancements/<uuid>.json` | 原版 | 达成时 | 成就清零 |
| 3 | 统计（挖掘/击杀/行走…） | `mainland/stats/<uuid>.json` | 原版 | 自动存档 | 统计清零 |

| 5 | **货币余额** | `mainland/data/oktsas_money.dat` | 本 mod（SavedData `oktsas_money`） | 自动存档 / 停服 | **钱没了**（这是唯一存着钱的地方） |

| 7 | 未开独立背包的世界共用的背包池 | `multiverse/global_inventories/<uuid>.nbt` | 本 mod | 同上 | 同上 |
| 8 | 家、`/back` 队列、传送开关、屏蔽名单、昵称、禁言、上次在线、首次进服 | `multiverse/essentials.json` → `players.<uuid>` | 本 mod | 每次变更立即写 | 家/地标记录消失、禁言失效 |
| 9 | `/powertool` 绑定的物品指令 | `multiverse/essentials.json` → `powertools.<uuid>` | 本 mod | 绑定时 | 绑定丢失（物品本身还在） |
| 10 | **领地**：主人、主人名、成员、单人标志 | `multiverse/res.json` | 本 mod | 每次变更立即写 | 领地数据丢失（土地不再受保护） |
| 11 | 市场挂单（谁是卖家） | `multiverse/market/listings.json` | 本 mod | 上架/买断/撤单 | 挂单与"该退给谁"丢失 |
| 12 | **邮箱**（待领物品：挂单到期、被撤单、世界删档邮寄） | `multiverse/market/mailbox.json` | 本 mod | 退件时 | 退回来的东西没了 |
| 13 | 垃圾桶"确认模式"、社交间谍、领地选区与粒子缓存 | **只在内存里**（不落盘） | 本 mod | — | 重启后回到默认（垃圾桶=关闭即销毁、社交间谍=关） |

> 第 5 项的文件名遵循原版 `SavedData` 规则（存档目录 `data/<数据名>.dat`，数据名就是代码里的 `oktsas_money`）。
> 我在开发环境是强杀服务端停的，所以没能实测到这个文件落地；**正式服正常 `/stop` 停服后它一定在**（可以用 `dir /s oktsas_money*` 找）。

## 1. 目录树（实测自开发服务器，注释了每层装什么）

```
<服务器根>/
├─ mainland/                              ← 主城（= server.properties 里 level-name 的值）
│  ├─ level.dat                           ← 原版世界数据（本 mod 的"世界出生点"不在里面，见 §2.1）
│  ├─ playerdata/<uuid>.dat               ← ★所有玩家的原版数据都在这里（不管他在哪个受管世界）
│  ├─ advancements/<uuid>.json            ← 成就（有玩家首次进服才创建）
│  ├─ stats/<uuid>.json                   ← 统计（同上）
│  ├─ data/                               ← 主世界的存档数据 → 里面就有 oktsas_money.dat（钱的唯一存放处）
│  ├─ DIM-1/  DIM1/                       ← 原版 下界 / 末地
│  ├─ region/ entities/ poi/              ← 主城区块
│  ├─ serverconfig/  datapacks/
│  └─ level.dat_old  session.lock
│
├─ resource_world/                        ← 一个受管世界（每个世界就是这样一个文件夹）
│  ├─ region/  entities/  poi/            ← 该维度的区块
│  ├─ data/                               ← 该维度的持久化数据（capabilities.dat / chunks.dat / raids.dat…）
│  └─ multiverse/
│     ├─ world.json                       ← 这个世界的设置（pvp/游戏模式/出生点/独立背包…）
│     └─ inventories/<uuid>.nbt            ← ★这个世界的独立背包（开了 separateInventory 才有）
│
├─ multiverse/                            ← 本 mod 的全局数据
│  ├─ essentials.json                     ← 家 / warp / powertool / 每个玩家的开关与禁言（players.<uuid>）
│  ├─ res.json   res-config.json          ← 领地数据 / 领地配置（单价、上限、管理员等级）
│  ├─ menus.json menu-config.json chatbuttons.json world-rules.json
│  ├─ shop/categories.json   shop/recycle.json
│  │                                       ← 商店价目表；0.2.6 起 recycle.json 是**数组**，
│  │                                         老的对象格式首次启动自动迁移并留 recycle.json.bak
│  ├─ market/listings.json  market/mailbox.json  market/blacklist.json
│  ├─ market/config.json                  ← 市场开关（永久单/费率/时长上限/栏位数，0.2.4 起）
│  └─ global_inventories/<uuid>.nbt        ← ★未开独立背包的世界共用的背包池
│
├─ ops.json  whitelist.json  banned-players.json  banned-ips.json  usercache.json
└─ mods/ config/ logs/ …
```

### 1.1 最关键的三个"反直觉"点

1. **受管世界没有自己的 `level.dat`，也没有 `playerdata/`**。
   实测 `resource_world/` 里只有 `data / entities / multiverse / poi / region`。
   原因是：受管世界借用主城的 level data（`DerivedLevelData`），而玩家 `.dat` 由
   `MinecraftServer` 用**主城**的存储访问来读写 → **所有玩家的 `.dat` 永远只在 `mainland/playerdata/`**。
   （这也是"受管世界的出生点必须由 mod 自己记录、不能存 level.dat"的原因。）
2. **一个玩家的背包可能分散在多个文件里**：只要世界开了 `separateInventory`，
   那个世界就有一份 `<世界>/multiverse/inventories/<uuid>.nbt`；
   没开的世界用 `multiverse/global_inventories/<uuid>.nbt`。搬家/备份时**两边都要拿**。
3. **钱不在 `multiverse/`**，在主城存档的 `data/` 下（`SavedData`）。只备份 `multiverse/` 会丢钱。

## 2. 逐项细节

### 2.1 原版玩家数据 → `mainland/playerdata/<uuid>.dat`
* 内容：位置与朝向、血量、饥饿、经验等级、药水效果、末影箱、**当前生效的那套背包**（未开独立背包时就是主背包）、
  以及 mod 附加在玩家身上的 capability（含 **Curios 饰品栏**，除非该世界开了独立背包，那部分会被搬到独立背包文件里）。
* 写时机：原版自动存档、玩家退出、正常停服（`/stop`）。
* 注意：**强杀进程（直接关窗口/`Stop-Process`）可能丢最后一次存档**，也会让 `oktsas_money.dat` 等 SavedData 不落盘 → 停服请用 `/stop`。

### 2.2 世界独立背包 → `<世界>/multiverse/inventories/<uuid>.nbt`
* 内容（NBT 根下两个键）：`inventory`（主背包 36 + 盔甲 4 + 主/副手）、`curios`（装了 Curios 才有）。
* 触发：**切世界**（把原世界的存下来、载入目标世界的；首次进入为空池）、**退出登录**、进服时若无存档就"接管"当前背包（不会吞东西）。
* 世界**删除/重置**前，这个池里的东西会**按 uuid 邮寄**到本人邮箱（在 `mailbox.json` 里），下次登录自动领取。
* **0.2.5 起，每次覆盖池子文件前会留一代备份 `<uuid>.nbt.bak`**（写盘走"临时文件 + 原子改名"，不会留下写了一半的半个文件）；
  `.bak` / `.tmp` 都不会被扫描，**只有 `<uuid>.nbt` 是当前生效的那一份** —— 池子内容不对时先看 `.bak`。
* 想手工搬一个玩家的独立背包：把对应 `<uuid>.nbt` 拷到新服同名世界的同名目录即可。

### 2.3 全局背包池 → `multiverse/global_inventories/<uuid>.nbt`
* 只有**没开** `separateInventory` 的受管世界之间才共用它；主城与它之间也会来回搬（进出受管世界时）。
* 格式与 §2.2 完全相同。

### 2.4 货币 → `mainland/data/oktsas_money.dat`
* 结构：`balances: [ { id: "<uuid>", amount: <double> } ]`，内部用 BigDecimal 两位小数记账。
* 只有"主世界存档"这一处，**没有第二份**。

### 2.5 `multiverse/essentials.json` 里的玩家段
```
essentials.json
├─ config        ← 全局配置（传送延迟/收费/冷却/家的上限/主城世界…）
├─ spawn         ← 主城出生点（一个坐标点）
├─ warps         ← 地标：名字 → 坐标点
├─ powertools    ← <uuid> → "物品id|指令"
└─ players
   └─ <uuid>
      ├─ homes        家：名字 → 坐标点
      ├─ backs         /back 队列（最新在末尾，长度 = backQueueSize）
      ├─ tptoggle     是否拒绝别人的传送请求
      ├─ afk / god / fly / vanish   对应开关的状态
      ├─ ignore       屏蔽名单（玩家名）
      ├─ nick         聊天前缀
      ├─ mutedUntil   禁言到期毫秒（Long.MAX_VALUE = 永久）
      ├─ muteReason   禁言理由
      ├─ lastSeen     上次在线毫秒（/seen 用）
      ├─ firstJoin    首次进服毫秒
      └─ lastName     最后已知名字（/unmute、/seen 靠它反查 uuid）
```
* 坐标点的字段：`world`（维度 id）、`x/y/z`、`yaw/pitch`、`label`、`at`。
* **运行中手改这个文件没用**：内存里的状态会在下次写盘时覆盖它 → 要改**先停服**。

### 2.6 领地 → `multiverse/res.json`
* 与玩家有关的字段：`owner`（主人 uuid）、`ownerName`、`members`（uuid → 名字）、
  `playerFlags`（uuid → 标志 → true/false，就是 `/res pset` 的单人设置）。
* 每次创建/改名/加成员/改标志都会立即写盘。
* 世界删除或重置时，该世界的领地会被**清空**（先按维度 id 匹配）。

### 2.7 市场与邮箱 → `multiverse/market/`
* `listings.json`：一条挂单含 `seller`(uuid) / `sellerName` / `item`(SNBT) / `price` / `createdAt` / `hours` / `label`。
  `hours` 是**每条挂单自己的时长**，`0` = **永久单**（0.2.4 起支持，永不过期、不会退回邮箱）。
* `mailbox.json`：`<uuid>` → 待领物品列表（物品 SNBT）。**玩家一登录就自动领取**并提示"已自动领取邮箱中的 N 个物品"。
* `blacklist.json`：物品 id 黑名单（与玩家无关，商店共用）。
* `config.json`（0.2.4 新增）：**与玩家无关的全局开关**（`allowPermanent` / `permanentFeeRate` /
  `maxHours` / `defaultHours` / `maxListings`）。**手改后 `/market config reload`（op4）热生效，不用重启**；
  删掉会回默认值。运行期手改 `listings.json` 仍然会被内存覆盖 → 改挂单请**停服**。
* **0.2.5 起，`listings.json` / `mailbox.json` / `blacklist.json` 读不出来时，mod 拒绝覆盖它们**
  （坏 JSON、被截断成 0 字节、空白、`null` 都算）：文件原样保留、日志打 `[Market] refusing to write ...`，
  同时**上架与购买会被拒绝**（提示要先修文件），直到把文件修好（或从备份还原）并**重启服务端**为止。
  这是故意的 —— 磁盘上那份是唯一还留着数据的副本。

### 2.8 只在内存里的玩家状态（重启即失效）
| 状态 | 说明 |
|---|---|
| 垃圾桶"确认模式" | `/trash confirm` 的开关（`ShopMenus` 里的一个 UUID 集合）→ 重启回到"关闭即销毁" |
| 社交间谍 | `/socialspy` 的开关（`EssentialsCommands` 里的集合）→ 重启关闭 |
| 领地选区 / 上次领地 / 粒子缓存 | `DomainManager` 的 `SELECTIONS` / `LAST_DOMAIN` / `LAST_OUTLINE` → 重启后要用 `/res wand` 重新点两个点 |
| 商店分类页上的玩家头颅 | 每次打开现取 uuid + 名字，不落盘 |

## 3. UUID ↔ 玩家名怎么对应

* 文件名是 **UUID**：`80cb7360-1fce-3187-8d3b-e0dfb38f4925.nbt` 这种。
* 找"这个 uuid 是谁"：
  1. 服务器根 `usercache.json`（原版，进过服的都有）；
  2. `multiverse/essentials.json` → `players.<uuid>.lastName`（本 mod 记录，离线也能查）；
  3. 游戏内 `/seen <名字>`、`/res admin list`（带主人名）。
* **玩家改名字不影响任何数据**（一切都按 uuid 走），只有按名字查的指令需要 `lastName` 帮忙。

## 4. 常见运维操作

| 想干什么 | 怎么做 |
|---|---|
| **整服备份** | 停服 → 整个服务器根目录打包（尤其 `mainland/`、`multiverse/`、每个世界文件夹） |
| 只备份"玩家相关" | `mainland/playerdata/` + `mainland/advancements/` + `mainland/stats/` + `mainland/data/`（钱）+ `multiverse/` + 各世界的 `multiverse/inventories/` |
| **把一个玩家整体迁到另一台服** | 拷 `mainland/playerdata/<uuid>.dat`、`mainland/advancements|stats/<uuid>.json`、`multiverse/global_inventories/<uuid>.nbt`、每个 `<世界>/multiverse/inventories/<uuid>.nbt`；再在目标服 `essentials.json` 里补他的 `players.<uuid>` 段（家/禁言等），钱用 `/money set <玩家> <金额>` 补 |
| 只搬"某个世界的装备" | 拷那个世界的 `multiverse/inventories/<uuid>.nbt` |
| 手动给玩家发东西 | 优先用游戏内 `/mail send <玩家>`（op4，手持物品）；其次停服改 `mailbox.json` |
| 手动改钱 | 停服改 `mainland/data/oktsas_money.dat`（NBT）**或**进服用 `/money set`（推荐） |
| 世界被删/重置后东西去哪了 | 该世界独立背包里的物品被**邮寄**给本人 → 他登录时自动领取；没登录过的就看 `market/mailbox.json` |
| **玩家报"我在某个世界的东西/饰品没了"** | 先 `/mv inventory inspect <玩家>`（op4，只读，0.2.5 新增）：列出他**每个池子文件**各有多少件背包物品/饰品、在哪个磁盘路径，读不出来的会单独标出；确认对不上再用 `/mv inventory recover <玩家>`（op4）把池子里的东西**全部邮件发给他**，原文件改名 `<uuid>.nbt.recovered`（**不会重复发放**，`.bak`/`.tmp`/`.recovered` 都会被跳过） |
| 找"某个玩家的家/地标" | `multiverse/essentials.json` → `players.<uuid>.homes` / 顶层 `warps` |

## 5. 危险操作清单（都踩过）

1. **手改数据文件一律"停服改"最稳**：mod 在运行期**随时会把内存里的状态整份写回**这些文件
   —— `essentials.json`、`res.json`、`menus.json`、`shop/*.json`、`market/listings.json`、
   `<世界>/multiverse/world.json`（每次加载都按真实文件夹名回写）—— 运行期手改**迟早被覆盖**。
   几个常被误当成"手改文件就能调"的，逐个说清楚：
   * `market/config.json`：**文件不存在**时启动会生成一份（写的是内置默认值）；文件存在但**读不出来**时
     mod **保留默认值、也不覆盖你那个坏文件**（只打一行 ERROR）。它是唯一一个能**热生效**的
     —— 改完执行 `/market config reload`（op4，0.2.4 起）；想稳也可以停服改。
   * `world-rules.json`：会被游戏内的 **`/mv rules exempt|level` 覆盖**（命令一改就把内存里的整份写回去），
     启动读盘后也会立刻回写一次 → **停服改**，改完重启生效。
   * `menu-config.json`：启动读盘后同样会**立刻按内存状态回写一遍**，游戏内切换也会覆盖它
     → **停服改**，运行期改基本等于白改。
   * `res.json`：**读不出来时整个 mod 拒绝写它**（见下面第 2 条），修好后 `/res admin reload` 才恢复写入。
2. **`/res admin reload` 在 0.2.3 及更早是"假 reload"**：只保存不重读，手改 `res.json` 再敲它**反而立刻被覆盖**。
   **0.2.4 起已改成真重读**：校验后替换内存、坏文件绝不清空、读不出来时连文件都不写；
   详见《总说明书》§14.10。即便如此，**手改 `res.json` 仍推荐停服改**。
3. **强杀服务端**：`oktsas_money.dat`（钱）和各个背包池可能没来得及落盘 → 停服请用 `/stop`，等它打印完成后退出。
   （0.2.5 起池子文件覆盖前会留一代 `<uuid>.nbt.bak`，真遇上这种事故还能从 `.bak` 救回上一代。）
4. **只备份 `multiverse/` 就以为备份全了**：钱在主城存档里、原版玩家数据在 `mainland/playerdata/` 里。
5. **删世界文件夹前**：里面的 `multiverse/inventories/*.nbt` 是玩家在那个世界的全部家当，
   用 `/mv delete` / `/mv reset` 会让 mod 自动邮寄回去（0.2.5 起**装饰栏物品也会一起邮寄**，
   0.2.4 及更早那份会因为键名写错而直接随文件丢掉）；**手动 `rm` 文件夹则直接丢**。
6. **改 `world.json` 的 `folder` 没用**：每次加载都会按真实文件夹名回写。
