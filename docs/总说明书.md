## 一、安装与部署

### 1.1 三个 jar 的关系

| jar | 装哪 | 必须吗 | 作用 |
|---|---|---|---|
| `onekeytosetaserver-0.2.6.jar` | **服务端 `mods/`** | 必须 | 全部功能：多元世界、领地、商店（含 NBT 商品）、市场、邮箱、垃圾桶、售卖区、世界独立背包、菜单、聊天按钮服务端、KubeJS 接口、Essentials 平替指令 |
| `oktsas_chatbridge-0.2.6.jar` | **客户端 `mods/`** | 可选 | 在 e33chat 聊天侧边栏底部画出指令按钮（默认「菜单 / 商店」）。不装照常玩，只是没那排按钮 |
| `e33chat-Forge-1.20.1-2.4.17.jar` | **客户端 `mods/`** | 可选 | 第三方聊天界面本体（作者 E33EPUS）。补丁要它才能画按钮 |

要点：

* **普通玩家不需要装任何东西**：所有界面都是原版箱子界面（`GENERIC_9xN`），纯原版客户端可用。
* 客户端额外放一份 `onekeytosetaserver-0.2.6.jar` 只多两件事：**头颅皮肤/商品图标更完整**，
  以及**聊天按钮列表由服务端下发**（服务端能统一管按钮）。**两个 jar 同时放不会再冲突**（见第十节）。
* 硬前置只有 Forge + Minecraft。**Curios / KubeJS / e33chat 都是软依赖**：不装则对应功能自动降级，不会拒绝启动。

### 1.2 安装

1. 服务端：把 `onekeytosetaserver-0.2.6.jar` 放进 `mods/`；
2. 客户端（可选）：放 `e33chat-Forge-*.jar` + `oktsas_chatbridge-0.2.6.jar`（+ 可选的 `onekeytosetaserver-0.2.6.jar`）；
3. 启动服务端，日志里出现下面几行就算成功（**日志是 GBK 编码**，PowerShell 用 `Get-Content -Encoding Default` 读）：

```
[MV] startup scan: N world(s) known, M in datapack, K runtime-only
[MV] server started: X/Y managed world(s) online
[Shop] 11 categor(ies), 833 item(s), 814 recycle price(s) (0 with NBT rules)
[Market] N listing(s), ... permanent=true (fee 10%), maxHours=240, defaultHours=24, maxListings=9
[Menu] player inventory inside GUIs: shown (A)
[ChatButton] N button(s) loaded
```

### 1.3 升级到 0.2.6（0.2.1 ~ 0.2.5 的老服都适用）

1. **停服**，备份 `multiverse/` 整个目录；
2. **0.2.1 及更早**还要把世界里已经放下的 4 种商店方块挖掉（方块注册已在 0.2.2 删除，旧方块会变成空气）；0.2.2 ~ 0.2.5 不用；
3. 删掉旧的主 mod jar，放 `mods/onekeytosetaserver-0.2.6.jar`；
4. 客户端：删 `oktsas_chatbridge-0.2.5.jar`，放 `oktsas_chatbridge-0.2.6.jar`；主 mod jar 有的话也换；
5. 启动后按需确认这几行（都只在**第一次**升级时出现）：
   * `[Shop] recycle.json upgraded to the NBT aware list format (a copy of the old file is at recycle.json.bak)`
   * `[Shop] 11 categor(ies), 833 item(s), 814 recycle price(s) (0 with NBT rules)`
   * `[Market] took down N listing(s) of banned items and mailed them back to their sellers`（有老挂单时才出现）
   * `[Shop] categories.json: added the category icons and the display order ...`（缺图标时才出现）

**数据兼容**：世界数据、玩家背包池、领地、经济、菜单、市场、邮箱格式都没变。
**0.2.6 只改了一处数据格式**：`multiverse/shop/recycle.json` 从「id → 价格」的对象改成
**条目数组**（`{itemId, nbt?, price}`），**首次启动自动迁移**并留 `recycle.json.bak`；
老的纯 id 条目迁移后语义不变（= 任何 NBT 的该物品都按这个价回收），老价目表、老玩家习惯都不受影响。
`categories.json` 只是多了新的 `books_potions` 分类和可选的 `nbt` 字段，老字段照读。
**0.2.6 还删除了 157 件商品**（盔甲/武器/工具/原矿方块/刷怪蛋，见第十七章），这些物品**从此不能买卖**。

## 二、开服 10 分钟速查

```mcfunction
# 1) 主城：server.properties 里 level-name=mainland（本 mod 不会把主城当多元世界管）

# 2) 开一个会定时重置的资源世界（独立背包 + 边界）
/mv create resource_world NORMAL DEFAULT 8936602591955350383
/mv modify resource_world autoReset true
/mv modify resource_world autoResetHours 8
/mv modify resource_world separateInventory true
/mv modify resource_world border 4500
/mv setspawn

# 3) 价格表：开箱就是 11 类 833 件（不用导），要改就
/shop edit                      # 手持物品进图形化改价（op3）
/shop nbt                       # op3：打印手上物品的 NBT（附魔/药水/名字），方便手写配置

# 4) 菜单与聊天按钮
/menu                           # 玩家打开主菜单（世界列表/服务器商店/自由市场/邮箱/垃圾桶/售卖区）
/sell                           # 玩家打开售卖区：放物品 → 确认出售两次 → 结算
/chatbutton gui                 # 图形化改 e33chat 侧边栏按钮（op4）

# 5) 钱与领地
/money give <玩家> 10000        # op3
/res wand                       # 玩家自己领法杖圈地，/res create <名字> 扣钱

# 6) 自由市场想"不限时"：改 multiverse/market/config.json，然后
/market config reload           # op4，热生效；/market config 查看当前设置（op3）
/market sell 1200 0             # 玩家：永久单（0 = 永不过期）；不写时长 = 用默认 24 小时
```

## 三、权限模型（原版 OP 等级，没有权限插件）

**op3 = 世界管理员，op4 = 全局管理员**（这两个定义定死不变）。

| 等级 | 拥有什么 |
|---|---|
| **op0 普通玩家** | `/mv tp`、`/mv menu`、`/menu`、`/res`（自己的领地）、`/shop`、`/sellall`、`/trash`、`/market`（含搜索/筛选/撤单）、`/mail`、`/money`、`/money pay`，以及 Essentials 的 `/spawn` `/home` `/warp` `/tpa` `/back` `/rtp` `/near` `/who` `/seen` `/afk` `/r` `/ping` `/getpos` `/compass` `/depth` `/suicide` `/workbench` `/anvil` `/ec` `/hat` `/repair` `/heal` `/feed` `/ignore` `/sethome` 等 |
| **op3 世界管理员** | 上面全部 + **除 `/mv tp` 外的所有 `/mv`**、`/mv rules`、`/setspawn` `/setwarp` `/delwarp` `/tppos` `/tphere` `/tpall`、`/god` `/fly` `/more` `/speed` `/vanish` `/broadcast` `/socialspy` `/invsee` `/lightning` `/exp` `/skull` `/firework` `/powertool`、`/mute` `/unmute` `/mutelist`、`/ess fee|delay|homes|fees|reload`、`/shop edit` `/shop price` `/shop recycle`、`/market blacklist *`、`/money give|take|set` |
| **op4 全局管理员** | 上面全部 + `/res admin *`、**菜单编辑器** `/menu edit|create|delete|rows`、`/nick`、`/ess main`、`/mail send`（给任意玩家寄物品）、**`/chatbutton`** |

### 3.1 管理员豁免（不会被世界规则强制）

`WorldPropertyListener` 会按世界配置强制游戏模式/飞行/饥饿/自动回血/禁 PvP；
**op3+ 默认全部豁免**，每一项可单独开关（配置在 `multiverse/world-rules.json`）：

```
/mv rules                                          # 看当前设置
/mv rules exempt <gamemode|flight|hunger|autoheal|pvp|all> <on|off>
/mv rules level <0-4>                              # 豁免等级，默认 3
```

### 3.2 中文参数怎么写（重要）

指令的**最后一个参数**都改成了整行读取，中文可直接写：

```
/res create 我的家      /home 我的家      /sethome 我的家      /setwarp 主城广场
/res tp 我的家          /res info 我的家  /res remove 我的家    /res admin delete 我的家
```

名字**后面还有别的参数**（名字在中间）时，必须用**英文双引号**：

```
/res rename "我的家" 新家          /res set "我的家" pvp on
/res pset "我的家" Steve pvp off   /res trust "我的家" Steve
```

更省事的写法（**站在自己的领地里**执行，不用写名字）：

```
/res set pvp on                    /res pset Steve pvp off
```

## 四、世界系统 `/mv`

### 4.1 世界就是"根目录下的一个文件夹"

```
<服务器根>/
  mainland/                    # 主城（= server.properties 的 level-name，不受本 mod 管理）
  resource_world/              # 一个受管世界
    region/ entities/ poi/     # 区块数据（原版格式）
    data/                      # 该维度自己的持久化数据
    multiverse/
      world.json               # 这个世界的全部设置
      inventories/             # 独立背包物品池（开了 separateInventory 才有）
    .hotload                   # 可选：不随开服加载，改成运行时 /mv load
  multiverse/
    menus.json  chatbuttons.json  world-rules.json  menu-config.json
    res.json  res-config.json  essentials.json
    shop/categories.json  shop/recycle.json
    market/listings.json  market/mailbox.json  market/blacklist.json
```

**由此得到的能力**：拷走一个文件夹 = 完整搬家（含设置和玩家物品池）；删掉文件夹 = 彻底重置；
`mainland/dimensions/` 目录**不会被使用**。

### 4.2 世界从哪来

* **开服自动识别**：根目录下凡是含 `region/` 或 `level.dat` 的文件夹都会被登记，并作为真正的维度加载（不需要 Mixin）；
* **在线加载**：`/mv load <文件夹名>`；
* **在线创建**：`/mv create <名字> [环境] [生成器] [种子]`。

### 4.3 出生点规则（0.2.2 重做）

* 每个受管世界的出生点记录在该世界文件夹的 `multiverse/world.json`（`spawnX/Y/Z`）；
* 新建/加载/启动时若还没设过，就写成 **`0, ~, 0`**，即 **0/0 的地表**（用原版高度图，**水也算地面**，
  所以 0/0 在海上时落点是**海面**；虚空世界用 `y=64`）；`/mv setspawn` 设过的世界**永不覆盖**；
* `/mv tp <世界>`、`/mv spawn`（= `/mv tp spawn`）都走这个出生点；
* **地底救援**：死亡重生/登录后如果落在**方块里 / 岩浆里 / 世界底部**，自动送回该世界出生点并提示；
  床重生、正常登录不受影响。

> 为什么不能像原版那样存进 `level.dat`：受管世界没有自己的 `level.dat`，
> 服务端用 `DerivedLevelData` 代管**主世界**的 level data，而它的 `setSpawn()` 是**空方法**。
> 所以主世界出生点是 0,0,0 时，在受管世界重生就会落到 0,0,0（地底）——这就是 0.2.2 修掉的那个现象。

### 4.4 每世界属性（`/mv modify <世界> <属性> <值>`）

| 属性 | 作用 |
|---|---|
| `pvp` | 关掉后玩家之间的伤害被拦下（含投射物） |
| `gameMode` | 进入/重生/登录时强制游戏模式 |
| `allowFlight` | 该世界允许飞行 |
| `hunger` | 关掉后饱食度/饱和度维持满值 |
| `autoHeal` | 每秒回 1 点血 |
| `border` | 世界边界尺寸（0 = 不动） |
| `keepSpawnInMemory` | 常驻加载出生点区块 |
| `playerLimit` | 人数上限（满员拒绝进入） |
| `blacklist` | 禁入名单（逗号分隔玩家名，`none` 清空） |
| `alias` | 显示别名（`none` 清空） |
| `hidden` | 隐藏世界：普通玩家 `/mv tp` 被拒 |
| `scale` | 该世界移动速度缩放（例如地狱 8 倍） |
| `respawnWorld` | 死亡后把你送回哪个世界（`none` 关闭）；`bedRespawn` 控制有床时是否仍回床 |
| `separateInventory` | 该世界使用**独立物品池**（见 4.6） |
| `autoLoad` | 是否随开服加载 |
| `autoReset` / `autoResetHours` / `newSeedOnReset` / `clearDataOnReset` | 定时重置（见 4.5） |
| `environment` | `NORMAL` / `NETHER` / `THE_END`（写错会容错成 NORMAL 并给日志提示） |

环境与生成器：`NORMAL`=overworld、`NETHER`=the_nether、`THE_END`=the_end；
生成器 `DEFAULT`（原版地形）、`FLAT`、`VOID`、`LARGE_BIOMES`、`AMPLIFIED`。

### 4.5 定时自动重置（资源世界那套）

```
/mv modify resource_world autoReset true
/mv modify resource_world autoResetHours 8
/mv modify resource_world newSeedOnReset true      # 重置后换新种子
/mv modify resource_world clearDataOnReset true    # 是否连 data/ 一起清（其它 mod 的按维度数据）
```

行为：每 5 秒检查一次 → 在 **10/5/2/1 分钟**与 **30 秒**时聊天栏高亮广播 → 到点先把世界内玩家送回**主世界出生点**
（下一次检查确认无人后再动手）→ 清空 `region/entities/poi`（按开关清 `data/`）→ 重新加载并广播完成。
想立刻重置：`/mv reset <世界>`。

### 4.6 世界独立背包（每世界可选）

* 开启：`/mv modify <世界> separateInventory true`；
* 范围：**主背包 36 格 + 盔甲 4 格 + 主手/副手**（装了 **Curios** 时**还包括饰品栏**）；
* 规则：进入开启该选项的世界 → 当前物品存入**原世界物品池**并清空 → 载入**目标世界物品池**（首次为空）；
  **回原世界自动还给你**；未开启的世界共用 `multiverse/global_inventories/`；
* 登录以存盘为准（无存盘就接管当前背包，**不会吞东西**），退出自动存盘；
* **0.2.5 修好的坑**：0.2.3/0.2.4 做快照时顺手把玩家身上**清空**，于是"首次进入这个世界"的玩家一登录饰品就被清掉，
  下一次保存再把这份"空状态"写回池子 → 永久丢失。0.2.5 快照**只读不删**，装不回去的物品进邮箱（见第十八节）；
* 世界**删除/重置前**，该世界物品池里的东西（含饰品栏）会**邮寄给本人**，在 `/mail` 领回；
* **不隔离**：经验、末影箱。

### 4.7 跨维度传送的安全策略（重要）

* 所有传送都在**服务器 tick 结束**时统一执行，绝不在实体 tick 里改维度；
* **默认只传送玩家**；载具/乘客直接拒绝；`create`、`railways`、`immersive_aircraft`、`automobility`
  命名空间的实体拒绝（这些跨维度最容易崩）；
* 传送前做序列化预检，失败则**回滚到原位置**并写日志；
* 落点自动搜安全位置（避开岩浆/岩浆块/仙人掌/火/营火；优先高度图给的**地表**，先强制加载该列区块）；
* 若有别的 mod 取消了"维度旅行事件"，原版会静默跳过 → 日志里会有 `travel event final ... allowed=false` 便于排查。

## 五、领地系统 `/res`（Residence 风格）

旧的 `/domain` 及其全部子指令**已删除**，旧数据 `multiverse/domains.json` 会在启动时自动迁移成
`multiverse/res.json`（旧文件保留不删）。

### 5.1 圈地流程

1. `/res wand` 拿「领地法杖」（带标记的金锄，**不能耕地**）；
2. **左键**点方块 = 第一个点，**右键**点方块 = 第二个点；
3. 点完开始用**村民交易的绿色粒子**画选区，**每 0.8 秒刷新**，只画 12 条棱、只画你 48 格以内的部分（大选区也不卡）；
4. 调高度：`/res height up <格数>` / `/res height down <格数>`；
5. `/res create <名字>` 建立 —— **这时才扣钱**。
   **0.2.5 的新保护**：如果领地存档 `res.json` 处于"锁定写入"状态（启动或 `/res admin reload` 时读不出来、
   或跳过过坏记录），`/res create` 会被**直接拒绝，并且一分钱都不扣**（见 §14.10）。

### 5.2 收费（按体积）

```
费用 = 长 × 宽 × 高 × 单价（默认 1.5 元/格）
例：64 × 64 × 1   = 4096 格    → 6144.00
    64 × 64 × 100 = 409600 格  → 614400.00
```

* **不设尺寸上限**；钱不够会提示「你没有足够的金钱。（需要 X，你有 Y）」并取消创建，**不欠费**；
* 一次性收费、**永久有效**（无续费/过期）；
* 单价：`/res admin price <单价>`（op4）或改 `multiverse/res-config.json`；
* **注意**：保护的就是你圈的**那个立方体**，`64×64×1` 只管那一层，上下不管。

### 5.3 七个保护标志（全部是"禁止项"）

`on` = 禁止外人，`off` = 允许外人。主人和 `/res trust` 的成员不受限，op4 无视一切保护。**默认 7 个全 on**。

| 标志 | 含义 |
|---|---|
| `breaking` | 破坏方块 |
| `placing` | 放置方块 |
| `interact` | 右键交互（按钮/拉杆/门/箱子/工作台） |
| `useitem` | 在领地内使用物品（打火石/水桶/骨粉/食物…） |
| `pvp` | 玩家之间战斗（双方位置都检查） |
| `explosion` | 爆炸破坏（TNT/苦力怕…） |
| `mobgriefing` | 怪物破坏方块（末影人搬方块/羊吃草…） |

```
/res set <领地> <标志> <on|off>            # 对所有人（外人）
/res pset <领地> <玩家> <标志> <on|off>    # 只对某个玩家（on=禁止他，off=允许他）
/res pset <领地> <玩家> <标志> remove      # 清除单独设定
/res flags                                # 列出全部标志
```

中英文都认（`breaking`/`破坏`、`pvp`/`对战`…）。**机器类破坏**（Create 机械、发射器、活塞、TNT）
在开了对应保护的领地里同样会被拦下，即使没有主人（属于"非玩家来源"，视为闯入者）。

### 6.2 服务器商店（可买可卖）

* 三页：**分类页 → 商品列表页（翻页，每页 45 件）→ 选数量页**；
* **分类页排布（0.2.2 按服主给的截图改的）**，窗口标题「**服务器商店**」：

```
第1行   .  .  .  .  .  .  .  .  .
```

  `blocks`方块(草方块) → `farming`农业(金锄) → `mobs`怪物掉落(腐肉) → `dyes`染料(青金石) → `everything_else`其他(铜锭)

  > **0.2.6 起没有「刷怪蛋」分类了**（74 个刷怪蛋整类删除并永久禁交易），分类从 12 个变成 11 个；

* **刷钱防护**：回收价 ≥ 买价的设置会被直接拒绝（`/shop recycle` 与图形化 `/shop edit` 两条路都拦），日志里记 warn；
* **NBT 商品（0.2.6 起）**：附魔书、药水这类"同名不同货"的物品可以单独上架/单独定价，
  买到的就是那件带附魔/药水的物品，见 §6.6；
* **永久禁交易（0.2.6 起）**：盔甲、武器、工具、原矿方块、刷怪蛋在**商店和自由市场都不能买也不能卖**，见 §6.7；
* 黑名单物品（`/market blacklist`）商店也拒收——两系统共用同一份黑名单。

### 6.4 改价

```
/shop edit                       # 手持要改的物品 → 打开图形化改价界面（op3）
/shop price <买价>                # 手持物品设买价（op3；商店里没有的会进「服主新增」分类）
/shop recycle <回收价>            # 手持物品设回收价（op3；≥买价会被拒绝）
/shop recycle remove             # 手持物品从回收表移除（op3）
/shop nbt                        # op3：打印手上物品的 NBT 摘要与完整 SNBT（写配置时复制用）

```

> 想按 id 改价请用图形化 `/shop edit`，或直接改 `multiverse/shop/categories.json`。

> 手持普通物品设价，改的是"该 id 的通配价"（任何 NBT 都算）。

| `/sellall` | 把**主背包 36 格**里有回收价的物品全部卖掉（不碰盔甲/副手/饰品），不可卖的原地不动 |

### 6.6 NBT 商品（0.2.6 新增）

商店的每件商品现在可以带 **NBT**：同一种物品的不同"货"能分别上架、分别定价。

* **怎么上架**：手持那件带 NBT 的物品 → `/shop edit` → 设买价/回收价 → 保存；
  界面预览里会显示 `附魔 锋利 V、耐久 III` 这样的摘要，并标注「这条只对带同样 NBT 的物品生效」。
* **怎么回收**：`categories.json` 的 `nbt` 字段是"这一条卖的是哪种货"；`recycle.json` 的
  **没有 `nbt` 字段 = 通配价**（任何 NBT 都收），**有 `nbt` 字段 = 精确价**（只有一致才收）。
  同一 id 同时有两条时，**精确价优先**。
* **匹配规则**：**忽略 `Damage`（耐久磨损）和 `RepairCost`**，其余（附魔、药水、自定义名、
  自定义模型、其它 mod 的键）**必须完全一致**。故意不做"只看关键字段"的模糊匹配 —— 那正是
  "改个名字冒充高价货"的漏洞。
* **内置例子**：`books_potions`（附魔与药水）分类里有 15 本常用附魔书 + 9 种常用药水，
  回收价表另有 5 条通配价（附魔书 80 / 药水 12 / 喷溅 18 / 滞留 25 / 药箭 4）。
  这几条价格都是**建议价**，`/shop edit` 随时改。

### 6.7 永久禁交易（0.2.6 新增，代码写死）

| 家族 | 判定方式 | 范围 |
|---|---|---|
| 盔甲 | 原版 `ArmorItem` / `HorseArmorItem`（含鞘翅、海龟壳、马铠） | 商店 + 自由市场，**都不能买、不能卖** |
| 武器 | `SwordItem` / 弓 / 弩 / 三叉戟 / 盾牌 | 同上 |
| 工具 | 镐斧锹锄 / 剪刀 / 钓鱼竿 / 打火石 / 刷子 / 胡萝卜钓竿 | 同上 |
| 原矿方块 | id 以 `_ore` 结尾（含深板岩变种） | 同上 |
| 刷怪蛋 | `SpawnEggItem` | 同上 |

* 这是**代码里的规则**，`market/blacklist.json` 改不动它、`/market blacklist remove` 也解不开；
  mod 装了别的附属（拔刀剑、枪械等）时，它们的"剑/镐/盔甲"只要继承了原版类，同样被拦。
* **故意没拦**：粗铁/粗金/粗铜、远古残骸、锭/宝石、箭矢（只有"矿石方块"被禁）。
  要连这些一起禁，说一声即可。
* 升级时，`categories.json` 里这些商品会被**自动删掉**、`recycle.json` 里对应行也会删掉，
  变成空的分类（例如刷怪蛋）一并移除；已经在市场上的这类挂单会被**撤下并邮寄回卖家**。

## 七、自由市场 `/market`

**挂单**：`/market sell <价格> [时长小时]`（把**主手物品**整组挂上去，一口价买断）。
每人同时最多 **9 个在售栏位**（`config.json` 的 `maxListings` 可改）；到期未卖出 → 物品自动退回**卖家邮箱**。
**时长写 `0` = 永久挂单：永不到期，也永远不会退回邮箱**（默认允许，可用配置关掉）；
**省略时长 = 用配置里的默认值**（出厂 24 小时）。

**永久挂单（0.2.4 新增，全部由 `multiverse/market/config.json` 控制，改完 `/market config reload` 即生效）**

```json
{
  "allowPermanent": true,        // 允许 /market sell <价格> 0
  "permanentFeeRate": 0.1,       // 永久单的管理费（0.1 = 10%）
  "maxHours": 240,               // 有限时长的上限（最小 1，最大 1000000；永久单不受它限制）
  "defaultHours": 24,            // 省略时长时用几小时
  "maxListings": 9               // 每人最多几个在售栏位
}
```

* `/market config`（op3）当场打印这几项；`/market config reload`（op4）重新读文件，**不用重启**；
* 文件坏了或写错类型 → **保留当前设置**并报错，不会把设置清成默认值；
* 永久单的费率是**固定一档**（默认 10%，等于原有限时长的最高档），不参与 1/2/3/5/8% 那套阶梯；
* 想彻底关掉永久单：`allowPermanent: false`（此时写 0 会被拒绝并提示）；
* **`hours` 是每条挂单自己的字段**：改 `config.json` 只影响**新挂单**和判定规则，不会改动老挂单的时长。
  想批量把老挂单变永久，得停服手改 `listings.json`（把每条 `hours` 改成 `0`）。

**界面**：`/market`（或 `/menu` 里的「自由市场」）打开箱子界面，**每页 45 件**，点图标即买断；
工具栏在**第 6 行**：

| 槽位 | 按钮 | 作用 |
|---|---|---|
| 45 | 上一页 | |
| 46 | 分类 | 点击循环：全部 → 方块 → 工具 → 武器 → 防具 → 食物 → 材料 |
| 47 | 我的挂单 | 开关；打开后**点自己的商品 = 撤回**（物品直接回背包） |
| 48 | 搜索 | 显示当前搜索词，点击清除（搜索词用指令输入） |
| 49 | 关闭 | |
| 50 | 当前筛选 | 分类/搜索/我的挂单/件数/页码 |
| 53 | 下一页 | |

商品图标的说明行会写「时长: **永久** §7(不过期) 费率: 10%」或「时长: 24h 费率: 3%」。

**指令**：`/market list`、`/market cancel <编号>`、`/market search <关键词>`、`/market cat <分类>`、
`/market mine`、`/market buy <编号>`、`/market gui`、`/market config [reload]`。

**黑名单（op3）**：`/market blacklist` 查看、`add|remove`（手持物品）、`addid|removeid <物品id>`；
被禁物品不能上架/显示/买断；加入黑名单时已有挂单会被撤下并**邮寄回卖家**。

**分类自动判定**：剑弓弩三叉戟=武器，镐斧铲锄剪刀钓竿=工具，头盔胸甲=防具，有食物属性=食物，
方块=方块，其余=材料。

**有限时长的管理费（阶梯，上限 10%；这一段是硬编码的，不可配置）**：

| 时长 | 费率 |
|---|---|
| ≤ 1 小时 | 1% |
| ≤ 6 小时 | 2% |
| ≤ 24 小时 | 3% |
| ≤ 72 小时 | 5% |
| ≤ 168 小时（7 天） | 8% |
| > 168 小时（含最长档） | 10% |

> 管理费是**成交时从卖家货款里扣**，不是上架时收。挂单本身免费；撤单也免费。
> **永久单会一直占着栏位**，不会自动清理。清理办法：本人 `/market cancel <编号>`；
> 管理员把该物品加进黑名单（`/market blacklist add`，手持物品）会**一次性撤下这件物品的全部挂单并邮寄回卖家**。

## 九、菜单系统 `/menu`（箱子菜单 + 在线编辑器）

**打开**：`/menu`（等同 `/mv menu`）。默认主菜单（5 行）：**世界列表、服务器商店、自由市场、我的邮箱、垃圾桶、售卖区、关闭**。

**自己改（op4）**：`/menu edit <id>`

* 布局界面：点任意格子 → 编辑那一格的按钮；空白浅灰格 = 新增；行数范围外的灰格点一下**自动扩展行数**；
* 按钮可设：图标（=手持物品）、名称、说明（`|` 分隔多行）、动作、参数；
* 五种动作：只展示 / **玩家身份执行指令** / 控制台身份执行指令 / 打开另一个菜单 / 关闭；
* 名称、说明这类文字会请你**在聊天栏输入**（`-` 留空、`cancel` 取消），输完自动弹回界面；
* 改完点「保存菜单」才写盘；布局最多 **5 行 = 45 个按钮**（第 6 行是工具栏）；
* 文件：`multiverse/menus.json`（可直接手改后 `/menu reload`）。

**指令一览**：`/menu`、`/menu <id>`、`/menu list`、`/menu edit <id>`、`/menu create <id> <标题>`、
`/menu rows <id> <1-5>`、`/menu delete <id>`、`/menu reload`（编辑类全 op4）。
**一键出售类按钮会自动加"再点一次确认"**（参数是 `sellall` 的按钮）。

## 十、聊天栏按钮 `/chatbutton` + 客户端补丁

### 10.1 三个 jar 的分工与"通道谁注册"

| jar | 装哪 | 通道 `onekeytosetaserver:chatbuttons` |
|---|---|---|
| `onekeytosetaserver` | 服务端（客户端可选） | **检测到补丁就让路**，自己不注册、不发送 |
| `oktsas_chatbridge` | 客户端 | **补丁注册并接收**，画按钮、执行指令 |
| `e33chat` | 客户端 | 提供侧边栏（补丁靠 Mixin 注入它） |

> 这条规则是 0.2.2 为了修「客户端启动崩溃」加的：以前两个 jar 都注册同名通道，Forge 抛
> `Channel ... already registered`，补丁加载失败 → 客户端起不来。现在**两个 jar 同时放也不会冲突**。
> 另外补丁对 e33chat 的依赖已改成**可选**：没装 e33chat 只是不画按钮，不会拒绝启动客户端。

### 10.2 按钮长什么样

* 位置：**聊天面板左侧边栏最底部**，竖向排列、从下往上；原版物品图标 + 物品框样式底框；
  鼠标悬停显示名字与绑定的指令；
* **点击 = 静默执行绑定指令**（不会往聊天栏打一行字），带冷却；
* 默认两个：**菜单**（`/menu`）、**商店**（`/shop`）；
* 配置存服务端 `multiverse/chatbuttons.json`，改完自动推送给装了补丁的客户端；
  服务端没装本 mod 时，客户端退回读自己的 `config/oktsas-chatbuttons.json`。

### 10.3 怎么改（op4）

```
/chatbutton gui                  # 图形化：45 个按钮格 + 工具栏（新增按钮/改名/改指令/换图标/保存并推送）
/chatbutton                      # 列表（等同 /chatbutton list）
/chatbutton add <显示名>          # 用手上的物品当图标新增（默认指令 menu）
/chatbutton name <编号> <新名字>
/chatbutton cmd <编号> <指令>      # 多条用 ; 隔开，例如 menu; say 你好
/chatbutton icon <编号>           # 用手上的物品当图标
/chatbutton cooldown <编号> <秒>
/chatbutton remove <编号>
/chatbutton save | reload         # 写文件+推送 / 重读+推送
```

### 10.4 注意

* 补丁靠 **Mixin 注入** e33chat（注入点：`renderSidebar` 末尾 + `mouseClicked` 头部），所以 **e33chat 升级后可能失效**；
* 两层保护：混入配置是 `required: false` + `defaultRequire: 0` —— **注入失败只记日志、按钮消失，不会崩客户端**；
* 实测基准版本 **e33chat 2.4.17**；换版本先用小号试。

## 十二、所有界面长什么样（格子布局）

### 12.1 通用规则（所有自家界面）

* 全是原版**箱子界面**（`GENERIC_9x1 ~ 9x6`），**纯原版客户端可用**；
* 6 行界面 = **54 个展示格 + 36 个玩家格（27 背包 + 9 快捷栏）= 90 格**，服务端与客户端格子编号**完全一致**
  （0.2.2 修掉了以前"服务端 99 / 客户端 90"的错位）；
* **展示格拿不动**（`mayPickup/mayPlace = false`），Shift+左键对展示格一律不动；
* **每次点击之后**服务端都会把真实状态（所有格子 **+ 鼠标上的物品**）整包重发，客户端本地"预测"的东西会被覆盖；
* 你**可以**在界面里正常整理自己的背包；想改成纯只读：
  `multiverse/menu-config.json` → `"showPlayerInventory": false`（重启生效，日志里会写 `hidden (B)`）。

### 12.2 服务器商店 · 分类页（标题「服务器商店」，6 行）

### 12.5 垃圾桶（6 行）

```
槽位   0 ~ 48   投物格（放进去的东西关闭界面即销毁；49 号除外）
槽位   50 ~ 53  投物格
槽位      49     红色按钮「立即销毁并关闭」（确认模式下必须点它才销毁）
```

* 默认模式：**关闭界面即销毁**，并提示销毁了多少个；
* `/trash confirm` 打开**确认模式**：关闭界面**不销毁**，物品**退回背包**；必须点 49 号红色按钮才销毁。
* 两种模式的状态**只在内存里**，重启服务器回到默认（关闭即销毁）。
* **0.2.3 修了一个真 bug**：以前这些投物格点上去**放不进东西**——服务端只把"玩家自己的背包格"交给原版逻辑，
  投物格被当作展示格拒绝，紧接着的重同步又把客户端本地放进去的东西撤掉，垃圾桶界面等于废掉。
  现在 0~48 / 50~53 都是正常容器格，左键/右键/Shift 都按原版行为工作（自检新增 `storage=ok` 断言守着）。

### 12.6 售卖区界面（`SellMenu`，`/sell` 打开）

```
槽位   0 ~ 44   把要卖的物品放进来（真容器格，左键/右键/Shift 都按原版工作）
槽位      45    实时统计：可卖几件、共多少钱、几件不可卖
槽位      49    确认出售（第一次点只提示，3 秒内再点一次才结算）
槽位      50~52  空
槽位      53    关闭（不卖，物品全部退回）
```

* **点一次不算**：第一次点 49 号只是亮成金色并提示"再点一次"；**第二次点才结算**；
* 结算时：**能回收的按回收价卖成钱**（一次入账并提示总数/总额），**不能回收的原样退回背包**
  （背包满则掉在脚下）；**一件都没确认就关界面 = 一件不卖、全部退回**，不会因为误按 Esc 丢东西；
* **Shift 点击双向搬运**：背包里 Shift 点击 → 进售卖区；售卖区里 Shift 点击 → 回背包；
* 回收价按第 6.6 节的 NBT 规则匹配：同名不同 NBT 的物品各自定价，匹配不上的退回；
* 界面上方 45 格是**内存容器**：放进去但没确认就关掉会退回，所以正常操作不会卡物品；
  只有服务器**崩溃/强杀**时，界面里还没确认的物品会丢（和原版箱子一样），请提示玩家别在界面里囤货。

### 12.13 其它原版界面（Essentials 提供）

### 13.5 `shop/categories.json` 与 `recycle.json`

`categories.json` 是**数组**，每项：

```json
{ "id": "blocks", "title": "方块", "icon": "minecraft:grass_block",
  "items": [ { "itemId": "minecraft:calcite", "buyPrice": 2.0 } ] }
```

| 字段 | 含义 |
|---|---|
| `id` | 分类 id（改商品归属时用得到，`/shop edit` 里的"分类"就是它） |
| `title` | 分类显示名（分类页图标上的名字） |
| `icon` | **分类页图标**的物品 id；留空 = 自动用该分类第一件商品 |
| `items[].itemId` | 商品物品 id |
| `items[].buyPrice` | 买价（回收价在另一个文件里） |
| `items[].nbt` | **可选**（0.2.6）。这一条商品带的 NBT，SNBT 字符串，例如 `{StoredEnchantments:[{id:"minecraft:mending",lvl:1s}]}`；**不写 = 普通物品** |

`recycle.json` **0.2.6 起是数组**（0.2.5 及以前是 `{ "id": price }` 对象，**首次启动自动迁移**并留 `recycle.json.bak`）：

```json
[ { "itemId": "minecraft:stone", "price": 0.18 },
  { "itemId": "minecraft:stone", "nbt": "{...}", "price": 0.5 } ]
```

| 字段 | 含义 |
|---|---|
| `itemId` | 物品 id |
| `price` | 回收单价 |
| `nbt` | **不写 = 通配**（任何 NBT 的该物品都按这个价收）；**写了 = 精确**（只有 NBT 一致才收） |

* 同一 id 同时有通配与精确条目时，**精确优先**；匹配时**忽略 `Damage` / `RepairCost`**；
* 出厂建议表就在服务端 `multiverse/shop/` 里（首次启动生成）；本仓库不附带 jar 或价格表压缩包。

**自动行为**：两个文件**任一为空** → 两者都被 jar 内出厂表覆盖；检测到 0.2.0 的"3 分类玩具默认值" → 也整体替换；
**0.2.6 升级**时还会：删掉永久禁交易的 157 件商品与空分类、补上「附魔与药水」分类和 5 条通配回收价
（只在缺失时补，不动你已有的价格）、把对象格式的 `recycle.json` 改写成数组；
**只有当分类缺 `icon` 时**才会补图标 + 按截图顺序重排，并在**第一次**留下 `categories.json.bak`（已存在不覆盖）。
之后完全以你的文件为准。

### 13.6 `menus.json` / `chatbuttons.json`

`menus.json`：`{ 菜单id: { id, title, rows, buttons: { "槽位": {icon, name, lore[], action, argument} } } }`
* `rows` 1~5（第 6 行留给编辑器工具栏），`action` ∈ `NONE / COMMAND_PLAYER / COMMAND_CONSOLE / OPEN_MENU / CLOSE`；
* 启动时：缺 `main` 就补默认主菜单；把按钮名里的「官方商店」改成「服务器商店」（幂等）；行数/槽位越界会被纠正。

`chatbuttons.json`：`[ { name, icon, commands[], cooldownSeconds } ]`
* 上限 **45** 条（超出启动时截断并记 warn）；
* 检测到"最早的一对默认值（菜单 `menu` + 多元世界 `mv menu`）"时自动升级成「菜单 / 商店」。

### 13.7 `market/` 四个文件与背包 NBT

* `config.json`（0.2.4 新增）：**市场开关文件，可以手改**，5 个字段 ——

  | 字段 | 类型 | 默认 | 含义 |
  |---|---|---|---|
  | `allowPermanent` | boolean | `true` | 是否允许 `/market sell <价格> 0`（永久单） |
  | `permanentFeeRate` | double | `0.1` | 永久单的管理费率（0.1 = 10%），夹在 `0.0~1.0` |
  | `maxHours` | int | `240` | 有限时长上限（小时），夹在 `1~1000000` |
  | `defaultHours` | int | `24` | `/market sell <价格>` 省略时长时用的小时数；**写 `0` = 默认就是永久单** |
  | `maxListings` | int | `9` | 每人同时在售栏位数，至少 1 |

  * 读的是**文件**，准确行为按**启动**与 **reload** 分开说（0.2.5 起统一口径）：
    * **启动时**：文件**不存在** → 生成一份默认值文件；文件**存在但读不出来**（坏 JSON / 写错类型）→
      **保留内置默认值**并打 `[Market] could not read ...`，而且**不回写、不覆盖**那个文件（留给你改）；
    * **`/market config reload`（op4）**：文件读不出来 → **保留当前内存值、不覆盖文件**，指令报红色失败提示；
      读成功才用文件的值替换内存（然后按夹取规则规范化）；
    * 也就是说：**mod 只在"文件不存在"或"读成功"时才写这个文件**，读到坏文件时你的原文件一个字节都不会被改；
  * 因为启动时缺文件会生成，所以"删掉它就等于回到出厂设置"只在**能正常生成**的前提下成立；
  * 夹取规则：`maxHours<1` 变 1、`>1000000` 变 1000000；`defaultHours` 不能超过 `maxHours`；
    `allowPermanent=false` 时 `defaultHours` 若是 `0` 会被改成 `24`。
* `listings.json`：一条挂单 = `{ id, seller(UUID), sellerName, item(SNBT), price, createdAt, hours, label }`；
  `hours > 0` = 有限时长，`hours <= 0` = **永久单**（永不过期）；每人上限 = `config.maxListings`，费率阶梯上限 10%；
* `mailbox.json`：玩家 UUID → 待领取物品列表（**领完就没了**）；
* `blacklist.json`：物品 id 集合（商店与市场共用）；**0.2.6 起还有一份"永久禁交易"规则写在代码里**
  （盔甲/武器/工具/原矿方块/刷怪蛋），它不在这个文件里、也改不动，见 §6.7；
* `global_inventories/<uuid>.nbt`、`<世界>/multiverse/inventories/<uuid>.nbt`：物品池快照
  （**删了就丢**；0.2.5 起每次覆盖前留一代 `<uuid>.nbt.bak`，写坏时靠它回滚）。

### 13.10 `res.json` 与 `market/listings.json` 的单条结构

**`res.json` 一条领地（Domain）**

| 字段 | 默认 | 含义 |
|---|---|---|
| `id` | 随机 8 位 | 领地 id（`/res admin delete` 用 id 最可靠） |
| `owner` / `ownerName` | `""` | 主人 UUID / 主人名 |
| `dimension` | `""` | 维度 id（世界删除/重置时按它清理） |
| `world` | `""` | 世界文件夹名（仅显示） |
| `name` | `""` | 领地名（≤24 字、不能有空格、同世界不重名） |
| `minX/maxX`、`minZ/maxZ`、`minY/maxY` | `0` | 立方体范围（旧版"无限高"取极值，按 384 计） |

| `createdAt` | 当前时间 | 创建时间戳 |

> 费用 = `(maxX-minX+1) × (maxZ-minZ+1) × 高度 × res-config.pricePerBlock`。

**`market/listings.json` 一条挂单（Listing）**

| 字段 | 默认 | 含义 |
|---|---|---|
| `id` | 随机 8 位 | 挂单编号（买下 / 撤单用它） |
| `seller` / `sellerName` | `""` | 卖家 UUID（发钱与退回依据）/ 卖家名（搜索匹配） |
| `item` | `""` | 物品 **SNBT** 字符串 |
| `price` | `0` | 一口价（≤0 不能上架） |
| `createdAt` | 当前时间 | 上架时间；到期判定用 `hours` |
| `hours` | `24` | 挂单时长（小时）。**`0` 或负数 = 永久单**（永不过期，也永不退回邮箱）；正数决定管理费率阶梯 |
| `label` | `""` | 纯文本标签（`名字 x数量`），供 `/market search` 匹配 |

> 同目录 `mailbox.json` = `uuid → 物品 SNBT 列表`；`blacklist.json` = 物品 id 数组；`config.json` = 市场开关（见 13.7）。
> 手改 `listings.json` 请**停服后改**：运行中任何一次成交/撤单/领邮件都会把内存里的列表整份写回。
> **0.2.5 起**：`listings.json` / `mailbox.json` / `blacklist.json` 各自带一把"**读不出来就不写**"的锁 ——
> 只要启动或运行期发现某个文件读不出来（坏 JSON、0 字节、截断），那个文件就一直保持原样不再被覆盖，
> 上架/买断/领邮件等会写它的操作会**被拒绝**，直到文件被修好并重启。

### 14.10 `/res admin reload`（0.2.3 之前名不副实，0.2.4 已修好，0.2.5 补齐锁定语义）

**0.2.3 及更早的问题**：源码（`ResCommand.adminReload`）只做了一件事 ——

```java
private static int adminReload(CommandContext<CommandSourceStack> ctx) {
    MinecraftServer server = ctx.getSource().getServer();   // 声明了但没用上
    DomainManager.save();                                    // 只保存，没有重新读盘
    ctx.getSource().sendSuccess(() -> Component.literal("已保存并重新读取领地数据"), true);
    return 1;
}
```

* 实际作用 = 把内存里的领地**写进** `multiverse/res.json`（等于手动存盘一次）；
* 不做的事 = 重新读取文件。所以「手改 res.json → `/res admin reload` 生效」的做法，
  结果正好相反：你刚手改的内容被内存里的旧数据**覆盖掉**；
* 提示文字「已保存并重新读取」是错的（只有保存）。

**0.2.4 的现状（真重读）**：

```java
DomainManager.ReloadResult r = DomainManager.reload();   // 读盘 → 校验 → 替换 → 回写
```

| 情况 | 行为 |
|---|---|
| 文件正常 | 读入全部领地 → 替换内存 → **按规范格式回写一次** → 回报「已重新读取 multiverse/res.json：N 个领地（之前 M 个）」 |
| 有记录缺 `id`/主人/维度 | 能读的都读进来，**跳过**坏记录；此时**不回写文件**（保留你的原文件好让你改），并且**文件进入锁定写入状态**（见下） |
| 文件是坏 JSON / 读不出来 / 是 0 字节或截断 | **拒绝**：内存里的领地保持不动、`res.json` **不写**，回报失败原因，并**锁定写入** |
| 文件不存在 | **拒绝**并**锁定写入**（提示：误删就从备份恢复；确实想清空就停服重启，届时才重建空库） |
| `res-config.json` | 顺便一起重读（单价/上限手改后不用重启）；坏文件保留内存当前值、不回写 |
| 空文件 / 截断文件 | **0.2.5 起不再被当成"空库"**：`""`、纯空白、字面量 `null` 都算"读不出来"，一律拒绝并锁定（0.2.4 会把它们静默当成空库，然后下一次保存把领地全冲掉） |

**0.2.5 的"锁定写入"（`storeIncomplete`）到底会发生什么**：

| 情形 | 行为 |
|---|---|
| 怎么进入锁定 | 启动或 `/res admin reload` 时 `res.json` 读不出来（坏 JSON / 0 字节 / 截断 / 文件不存在），**或者跳过了至少一条坏记录** |
| 提示颜色 | `/res admin reload` 在"跳过坏记录"的情况下报**黄色**提示（不是绿色成功），并写明"已锁定写入，修好它们再 `/res admin reload`" |
| 写文件 | 一律拒绝，日志写 `[Res] refusing to write ...` —— 文件里那些内存中没有的记录**不会被抹掉** |
| 建领地 | `/res create` 在**扣费之前**就被拒绝，提示"已取消创建，**没有扣费**" → 不会再出现"钱扣了、领地没存住、重启就没了" |
| 删领地 | `/res remove`、`/res admin delete` 在锁定期间**直接拒绝** |
| 改名 / 转让 / 设标志 / 加成员 | 仍然能在内存里生效，但成功消息后面会**追加红色警告**："领地存档被锁定，这次改动只在内存中，重启后会还原" |
| 怎么解除 | 修好（或从备份恢复）`multiverse/res.json` 里的坏记录，再 `/res admin reload` **成功一次**；或者修好后重启 |

**额外的安全闸**：只要 mod 发现 `res.json` 读不出来（开服时或 reload 时），它会把整个领地存档置为"锁定写入"
（内部标志 `storeIncomplete`，日志写 `[Res] refusing to write ...`），直到文件被修好并且**成功 `/res admin reload` 一次**（或修好后重启）——
这样"文件被同步盘/杀软弄坏 → 服务端照常跑 → 某次保存把领地全冲掉"这条数据丢失链被切断了。
**0.2.5 把这个闸门扩展到了"跳过坏记录"**：以前 reload 跳过坏记录后还能继续写，下一次保存就把那些没读进内存的记录抹掉了；
现在跳过即锁定，坏记录会一直留在文件里等你修。

**推荐用法**：

* 正常运营：`/res admin reload` 可以放心用（它现在真的按名字工作）；
* 但**改文件仍然是"停服改"最稳**（`res.json` 在运行期随时可能被内存状态整份覆盖）；
* 一旦看到**黄色**的 reload 提示或建/删领地被拒绝，先按上面"怎么解除"把 `res.json` 修好，别急着重启。

### 14.9 指令里最容易踩的坑（全部来自源码）

1. **引号只跟参数类型有关**：
   * `word()` —— 不能有空格，**中文可写但不加引号也可以**：用在 `/mv` 的世界名与属性、`/money|/mail|/market` 的玩家名、`/market <编号>`、`/market cat <分类>`、`/shop buy <物品id>`；
   * `string()` —— **中文/含空格必须加英文双引号**：只有 `/res rename <名字>`、`/res set <名字> …`、`/res pset <名字> …`、`/res trust|untrust|transfer|give <名字> …` 这几处；
   * `greedyString()` —— 吃完整行，**中文可不加引号且可带空格**：`/mv modify … <值>`、`/mv menu create <标题>`、`/market search <关键词>`、`/menu create <标题>`、`/chatbutton` 的名字与指令、Essentials 的 `/warp /home /sethome /afk /r /broadcast /nick /powertool /mute <原因> /ess main`。
   * 最容易记混：**`/res create <名字>` 不用引号，但 `/res set <名字> <标志> <on>` 的名字要引号**。
2. **必须手持物品**：`/shop price`、`/shop recycle`、`/shop recycle remove`、`/market sell`、`/market blacklist add|remove`、`/mail send`、`/chatbutton icon`、`/hat`、`/more`、`/powertool <指令>`。
3. **只能由玩家执行**（控制台/命令方块会失败）：`/mv tp`、`/mv tp spawn`、`/mv setspawn`、`/money`（含 pay/give/take/set）、`/shop edit|price|recycle`、`/sellall`、`/trash`、`/market sell|cancel|buy`、`/mail`、`/menu edit`、`/chatbutton gui`，以及几乎全部 Essentials 传送/工具指令。
4. **对方必须在线**：`/money pay|give|take|set`、`/mail send`、`/res trust|untrust|transfer|give`、`/heal|/feed|/god|/fly|/speed|/invsee|/clearinventory|/lightning|/exp|/skull|/mute <玩家>`。
5. **数值边界由 Brigadier 直接挡**（不是提示而是语法错误）：`/shop buy` 1~2304、
   `/market sell` 小时 **0~1000000**（`0` = 永久；超过 `config.maxHours` 会被指令**拒绝并提示**，不是语法错误）、
   `/menu rows` 1~5、`/chatbutton` 编号 1~45 与冷却 0~600、`/ess delay` 0~60、`/ess homes` 1~100、
   `/res height` 1~384、`/speed` 0~10、`/exp` -100000~100000、`/near` 1~10000、`/mv rules level` 0~4。
6. **不落盘的状态**：`/trash confirm`（垃圾桶模式）、`/socialspy`（重启回到默认）。
7. **`/chatbutton cmd` 的分隔符是 `;` 或 `|`**，因此被绑定的指令里不能再出现这两个字符；开头的 `/` 会被自动去掉。
8. **聊天按钮上限 45 个**（GUI 只画前 45 个）。
9. **Essentials 某条指令"不存在"**：先看日志 `[Ess] /xxx is already registered on this server, skipping ours`
   —— 说明同名根指令被原版/别的 mod 占了，mod 主动跳过（避免启动报错）。
10. **`/menu list` 与 `/mv menu list` 权限不同**（所有人 vs op3），`/menu reload`(op4) 与 `/mv menu reload`(op3) 也不同。
11. **`/sellall` 只卖主背包 36 格**（盔甲、副手不动）。
12. **`/mail` 是"领取"而不是"收件箱列表"**：执行就把物品塞进背包（满了掉地上）。
13. **豁免是给管理员用的**：`/mv rules exempt … on` = "op3 及以上不被该世界规则约束"，普通玩家永远受约束。

## 十五、KubeJS 接口（软依赖，可选）

装了 KubeJS 的整合包里，脚本会多出一个全局对象 **`oktsas`**（没装 KubeJS 完全不受影响）：

```js
oktsas.version()

// 世界
oktsas.worlds() / loadedWorlds() / isLoaded('resource_world') / worldInfo('resource_world')
oktsas.loadWorld('resource_world') / unloadWorld(...) / resetWorld(...) / deleteWorld(...)
oktsas.createWorld('新世界', 'NORMAL', 'DEFAULT', 12345)
oktsas.setWorldProperty('resource_world', 'pvp', 'false')      // 等价 /mv modify

// 经济
oktsas.money(player.username) / setMoney(name, 1000) / addMoney(name, 500)
oktsas.takeMoney(name, 100) / transferMoney(from, to, 50)

// 领地（方法名沿用 domain）
oktsas.domains() / domainAt('resource_world', x, y, z) / deleteDomain('id或名字')

// 商店与市场
oktsas.shopPrice('minecraft:diamond') / setShopPrice(id, 200) / setRecyclePrice(id, 50) / removeFromShop(id)
oktsas.marketListings() / marketBlacklist() / banMarketItem('minecraft:bedrock', true)

// 邮箱
oktsas.mailboxSize(player.username) / mailItem(player.username, 'minecraft:diamond', 3)
```

玩家参数可以写**在线玩家名**或 **UUID 字符串**；所有方法都不会抛异常打断脚本（失败返回 false/0/空列表）。

## 十六、故障排查 / 常见问题

| 现象 | 检查 |
|---|---|
| 开服报「另一个程序已锁定文件的一部分」 | 已经有服务端在跑（或上次没退干净）→ 关掉再启动 |
| 世界里商店方块变成空气 | 0.2.2 删掉了 4 个商店方块，旧方块会消失 → 用 `/shop` `/market` `/trash` `/sellall` 或 `/menu` |
| 客户端启动崩 `Channel ... already registered` | 说明客户端里是**旧版**的两个 jar 混装 → 两个都换 0.2.2 |
| 界面里 Shift+左键能拿走商品 | 不应该（0.2.2 已修）→ 把 `multiverse/menu-config.json` 的 `showPlayerInventory` 改成 `false` 再试并给我日志 |
| 界面里东西和显示不一致/打开就报错 | 也是格子数问题，0.2.2 已修；若仍出现请发日志 |
| 世界没被识别 | 文件夹里要有 `region/` 或 `level.dat`；名字不能以 `.` 开头；不在忽略名单（`config`/`mods`/`logs` 等）里 |
| `/mv tp` 没反应 | 日志搜 `travel event final ... allowed=false`：别的 mod 拦了维度旅行事件 |
| 世界数据跑到 `mainland/dimensions/` 里 | Mixin 没生效 → 检查 jar 的 `MANIFEST.MF` 是否有 `MixinConfigs: onekeytosetaserver.mixins.json` |
| 新世界出生点在海里 | 0/0 正好是海：高度图把水算地面，落点就是**海面**（原版语义）。想换位置：站在目标点 `/mv setspawn` |
| 价格不对 | 直接改 `multiverse/shop/*.json`，或 `/shop edit`；`/shop` 打开时会重新读入 |
| 日志中文乱码 | 日志是 **GBK**：`Get-Content -Encoding Default` |
| 聊天按钮不显示 | ① 客户端装了 `e33chat` + `oktsas_chatbridge` 吗；② 服务端 `/chatbutton list` 有没有按钮、`/chatbutton save` 重推；③ 客户端日志搜 `ChatBridge`（注入失败只会打日志） |
| `/res set 我的家 pvp on` 报错 | 名字在中间要加引号：`/res set "我的家" pvp on`；或站在自己领地里写 `/res set pvp on` |
| 想让挂单**永不过期** | `/market sell <价格> 0`（永久单）；想改"默认/上限/费率/栏位数"就编 `multiverse/market/config.json`，再 `/market config reload`（op4）。老挂单要一起变永久：停服把 `listings.json` 里的 `hours` 改成 `0` |
| `/market sell` 说过期时间太长被拒 | 超过 `config.maxHours`（出厂 240 小时）；要么改配置，要么写 `0` 挂永久单 |
| 手改 `res.json` 后 `/res admin reload` 报"文件不存在/读不出来" | 内存里的领地**没被动、文件也没被覆盖**；按提示修好文件再 reload。另外在这之前 mod 会拒绝写 `res.json`，重启或成功 reload 后恢复 |
| 手改 `res.json` 后忘了 reload | 直接重启服务器也一样（启动本来就会读盘），别在运行期反复手改 |
| `/res create` 被拒且提示"没有扣费" | **0.2.5 的保护行为**：`res.json` 处于锁定写入状态（读不出来或含跳过的坏记录）。修好文件 → `/res admin reload` 成功一次即恢复；期间**钱不会白扣** |
| `/res admin reload` 报的是**黄色**而不是绿色 | 同样表示"跳过了一些坏记录，已锁定写入"。这些记录还留在文件里，修好后再 reload 一次即可；锁定期间别急着建/删领地 |
| 玩家切世界/重登后**饰品不见了** | 确认服务端 jar 已是 **0.2.6**（0.2.3/0.2.4 有"快照顺手清空"的缺陷，0.2.5 修好）。已丢的先用 `/mv inventory inspect <玩家>` 看池子里还剩几件；还在的可以用 `/mv inventory recover <玩家>` 全部邮寄给他（池子文件会改名 `.recovered`） |
| 池子文件旁边多了 `xxx.nbt.bak` / `xxx.nbt.recovered` | 正常：`.bak` 是 0.2.5 每次覆盖前留的上一代备份；`.recovered` 是 `/mv inventory recover` 处理过的文件（不再加载，也不会重复发放）。都不建议手删 |
| 删/重置独立背包世界后，玩家说"东西多了一份" | 0.2.5 的已知取舍（见第十八节第 19 条）：快照不再从玩家身上拿走东西，离线玩家可能"身上一份 + 邮箱一份"。宁可多给不可少给；要杜绝就先删掉对应池子文件或让玩家在线再操作 |
| 市场挂单/邮箱突然"写不进去"、操作被拒 | 0.2.5 的写锁：对应的 `listings/mailbox/blacklist.json` 读不出来，文件保持原样不再被覆盖。修好该文件后重启服务端 |

## 十七、0.2.6 更新说明（商店 NBT / 售卖区 / 永久禁交易）

本版三件事：① **商店支持 NBT**（附魔书、药水这类"同名不同货"可以单独上架、单独定价）；
② **售卖区**：把任意物品放进箱子、二次确认后自动识别并卖出，不可卖的原样退回
（顺带补上这个界面一直缺的游戏内入口）；③ **盔甲 / 武器 / 工具 / 原矿方块 / 刷怪蛋永久禁止交易**
（商店与自由市场都不能买、不能卖）。

### 17.1 商店 NBT

* **数据**：`categories.json` 的 `items[].nbt`（可选，SNBT 字符串）；`recycle.json` 改成条目数组，
  `nbt` **缺省 = 通配**（任何 NBT 都收），**写了 = 精确**（只有一致才收）；
* **匹配**：精确条目优先于通配条目；比较时**忽略 `Damage`（耐久磨损）与 `RepairCost`**，其余（附魔、药水、
  自定义名、CustomModelData、其它 mod 的键）**全部比较**；故意不做"只看关键字段"的模糊匹配；
* **交易**：买到的就是模板那件（附魔书带附魔、药水带效果）；卖出只收与条目一致的变体，不匹配的退回；
* **命令**：`/shop edit`、`/shop price`、`/shop recycle` 都改成按手持物品的**完整 NBT** 操作；
  新增只读 `/shop nbt`（打印 NBT 摘要 + 完整 SNBT）；
* **兼容**：老表（纯 id）迁移后都是通配价，**老玩家卖普通物品的行为一点没变**；
* **内置**：`books_potions`（附魔与药水）分类 15 本常用附魔书 + 9 种常用药水（建议价），
  回收表 5 条通配价（附魔书 80 / 药水 12 / 喷溅 18 / 滞留 25 / 药箭 4）。

### 17.2 售卖区（`/sell`）

* **入口**：`/sell`、商店分类页 46 号槽、主菜单 24 号槽（默认菜单；老的 `menus.json` 里如果还是 `sellall`，
  把参数改成 `sell` 就变成售卖区）；
* **流程**：放物品 → 点「确认出售」→ **3 秒内再点一次** → 自动结算：能卖的按回收价入账，不能卖的**原样退回**；
* **没确认就关界面 = 一件不卖、全部退回**；Shift 点击双向搬运（背包↔售卖区）；
* `/sellall` 仍然存在，修成**只卖主背包 36 格**（以前实际会连身上盔甲、副手一起卖，和文档写的"36 格"不一致）；
* 界面里 45 格是内存容器，正常关闭会退回；只有服务器崩溃/强杀时界面里未确认的物品会丢（和原版箱子一样）。

### 17.3 永久禁交易

* **五类**：盔甲 / 武器 / 工具 / 原矿方块 / 刷怪蛋 —— 按**原版物品类**判定（`ArmorItem`、`SwordItem`、
  `DiggerItem`、`SpawnEggItem`、id 以 `_ore` 结尾……），所以 mod 附带的剑/镐/盔甲只要继承了原版类同样被拦；
* **商店**：升级时直接从价目表删掉这些商品（共 157 件），买不了也卖不了；空出来的分类（刷怪蛋）一并删除；
* **市场**：上架、购买都拒绝；**已经在售的**在启动时被撤下并**邮寄回卖家**；
* **黑名单**：`/market blacklist` 对这类物品**无效**（加不了、也解不开），`blacklist.json` 里不会出现；
* **故意没拦**：粗铁/粗金/粗铜、远古残骸、锭/宝石、箭矢 —— 只有"矿石方块"被禁。要连这些一起禁说一声。

| `shop/recycle.json` | 对象 → 数组；自动迁移，改前留 `recycle.json.bak`；老的纯 id 行语义不变（通配） |

## 十八、0.2.5 更新说明（饰品丢失修复 + 数据安全写锁）

> 这一版**没有新增任何游戏功能**，全部是数据安全修复 + 文档修正。升级不需要转换任何文件（见 1.3）。

### 17.1 Curios 饰品丢失：真正的原因**不是格式不兼容**

运维侧的缺陷报告把根因写成"池子文件格式与 Curios 的 `loadInventory` 不兼容"。**这个结论是错的**：
0.2.5 对照 Curios 5.14.1 的 `CurioInventoryWrapper` / `CurioStacksHandler` / `DynamicStackHandler` 逐条核过 ——
`saveInventory` 与 `loadInventory` 用的是**同一套结构**（`Identifier` / `Stacks` / `Cosmetics`），
`DynamicStackHandler` 就是 `ItemStackHandler` 且不覆写序列化，**写出去的池子和读回来的池子是同一个布局**。

真正的原因是一串连锁，**每一环都在 mod 这边**：

| # | 环节 | 0.2.3 / 0.2.4 的实际行为 |
|---|---|---|
| 1 | **快照顺手清空** | 做快照用的 `saveInventory(true)`，那个 `true` 就是"清空"。于是在"首次进入这个世界、还没有池子文件"的分支里，玩家一登录就被**悄悄清掉饰品栏**（背包却不清，两者行为还不一致） |
| 2 | **下一次保存把空状态写回** | 被清空之后玩家身上是空的，退出/切世界再快照一次，池子里那些饰品就被"空列表"覆盖 —— 这才是**永久丢失**的那一步 |
| 3 | **失败静默** | `loadInventory` 只往**空槽位**里放东西，放不进去的既不报错也不返回；`load` 只在抛异常时才打日志 → 装不回去时没有任何提示 |
| 4 | **客户端未同步** | Curios 饰品栏是客户端镜像，靠 `SPacketSyncStack` 同步。装回饰品后**一个包都不发**，玩家看到的仍是空饰品栏，重登才恢复 —— 报告里"时好时坏、必须反复重登"就是这一条 |
| 5 | **附带 bug** | 删/重置世界时 `mailCurios` 读的键是 `CosmeticStacks`，而 Curios 写的键叫 `Cosmetics` → **装饰栏物品从来没被邮寄过**，随池子文件一起删掉了 |

### 17.2 新的安全规则（0.2.5 起长期有效）

* **快照永不清空玩家**：做快照只记录，不动玩家身上任何一件东西；清空改成独立动作、只在该清的时候清。
* **先读成功，才允许清空**：必须先把池子文件**整份读进内存并解析成功**，才允许动玩家；读不出来就**原样保留**、
  玩家身上东西不动、文件**一个字节都不写**（登录路径、切世界路径都是这样）。
* **放不回去的饰品进邮箱**：槽位类型没了、槽位被占、下标越界这类装不回去的物品**不丢**，
  统一发到玩家邮箱（`/mail` 领取）并打 ERROR 日志；背包部分数量对不上也会记 ERROR。
* **写文件原子 + `.bak` 备份**：写池子走"先写临时文件 → 原子改名"，覆盖前留一代 `<uuid>.nbt.bak`。
* **客户端同步**：装回之后逐槽补发同步包（饰品栏 + 装饰栏），饰品栏当场就能看见，不用重登。
* **`/mv inventory` 两条补救命令（op4）**：
  * `/mv inventory inspect <玩家>` —— **只读**：列出该玩家每个池子文件里有多少件背包物品、多少件饰品；
  * `/mv inventory recover <玩家>` —— 把该玩家所有池子里的东西**全部邮件发给他**，用完的池子文件**改名为
    `<uuid>.nbt.recovered`**（改名的文件不再被加载，所以**不会重复发**）。
    这是**故意**走"绝不删除"路线：恢复出来的东西进背包/邮箱，玩家自己装回饰品栏即可。

### 17.3 池子文件格式没有变（老文件直接能读）

* 编解码改用 Curios 自己存档用的那一对方法（`serializeNBT` / `deserializeNBT`），**键名与层级一个字都没改**：
  仍然是 `Stacks` / `Cosmetics` / `Identifier`；
* 所以 **0.2.0 ~ 0.2.4 写出来的池子文件，0.2.5 直接能读，不需要任何转换、也不需要重开世界**；
* 自检里专门有一条 `legacyShape=true` 断言这件事（写出的池子仍是老布局）。
* 唯一要注意的：**如果饰品已经被 0.2.3/0.2.4 覆盖成空了**，那部分数据在文件里本来就不存在了，
  只能从你自己的备份或池子旁边的 `.bak` 里找回（用 `/mv inventory inspect` 先确认是不是 0 件）。

### 17.6 本版引入的一个已知取舍（删/重置独立背包世界可能重复给一份）

**现象**：删除或重置一个 `separateInventory=true` 的**独立背包世界**时，如果该玩家**离线**、而且自己身上
还带着同样那批东西，那么他重新登录后会看到"**身上一份 + 邮箱一份**"。

**为什么会这样**：删/重置世界会把该世界池子文件里的东西**寄回**给主人；而 0.2.5 起快照**不再从玩家身上拿走
任何东西**（本来就该这样），所以池子里那份和身上那份会同时存在。

* 受影响的**只有** `separateInventory=true` 的独立背包世界（共享世界用的是全局池，删世界不会动它）；
* 背包物品在 0.2.4 就是这么做的（老行为），0.2.5 只是把**饰品**也归到同一条规则下；
* 这是**故意的取舍**：宁可多给、不可少给。要杜绝，删/重置世界前先把对应玩家的池子 `.nbt` 删掉
  （`multiverse/inventories/` 或世界文件夹下的 `multiverse/inventories/`），或者让玩家**在线**再操作。

   菜单 24 号槽；命令版 `/sellall` 仍然存在（只卖主背包 36 格）。**没确认就关界面 = 一件不卖、全部退回**。

    所以第 5 行最后 4 格是**永远为空的死格**（不会报错，只是没用）；改别人背包是直接生效的，小心使用。
11. **垃圾桶的两种模式状态只在内存里**（`/trash confirm`），重启服务器回到默认「关闭即销毁」；
    售卖区没有"模式"，它始终要求二次确认。

    改 `market/config.json` 只影响**新挂单**与到期判定规则；老挂单想一起变永久，得停服手改 `listings.json`（`hours: 0`）。
13. **永久挂单没有任何"下线"机制**：`allowPermanent` 改成 `false` 只是**不让再挂新的**，
    已经挂上去的永久单照样不删（想清就 `/market cancel` 或 op3 把该物品加黑名单，会连同挂单一起撤下并邮寄回卖家）。
14. **`res.json` 读不出来时 mod 会拒绝写它**（防止把领地整份冲掉）：修好文件后用 `/res admin reload` 或者重启即可恢复写入。
    **0.2.5 起范围更大**：**跳过坏记录**同样会锁定写入（`/res admin reload` 报黄色提示），
    锁定期间 `/res create`、`/res remove`、`/res admin delete` 被拒绝（**且不扣费**），
    其它改动会在成功消息后追加红色警告；0 字节/截断的 `res.json` **不再被当成空库**。
15. **0.2.5 起，池子里"放不回去"的物品会进邮箱**（`/mail` 领取）并写 ERROR 日志，而不是被静默丢掉；

16. **池子文件 0.2.5 起有 `.bak` 备份**（每次覆盖前留一代 `<uuid>.nbt.bak`）；已被 0.2.3/0.2.4 覆盖成空的饰品，
    文件里已经没有数据，只能从备份/`.bak` 找回（先用 `/mv inventory inspect <玩家>` 确认）。
17. **`/mv inventory recover <玩家>`（op4）会把东西发到邮箱并把池子文件改名 `.recovered`** —— 这是故意的：
    走"绝不删除"路线，玩家自己在背包里收好、再装回饰品栏；改名后该文件不再被加载，所以**不会重复发放**。

    * 背包物品在 0.2.4 就是这么做的（老行为），0.2.5 只是把饰品也归到同一条规则下；
    * 这条是**故意的取舍**：宁可多给、不可少给。要杜绝，删/重置世界前先把 `multiverse/inventories/`
